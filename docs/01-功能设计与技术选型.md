# CodeDoc 功能设计与技术选型

> 当前实现基线。CodeDoc 用本地桌面流程整理软件著作权源程序材料；它帮助减少格式与内容准备错误，但不替代登记机构审查，也不构成法律建议。版本、发布和更新状态分别以 [`VERSIONING.md`](VERSIONING.md)、[`RELEASE_PACKAGING.md`](RELEASE_PACKAGING.md) 和 [`04-通用应用内更新技术方案.md`](04-通用应用内更新技术方案.md) 为准。

## 一、产品定位

- **一句话**：离线扫描本地工程，完成代码清洗、前后段截取、显式分页、风险校验与 PDF、DOCX、TXT 导出。
- **目标用户**：需要准备软件著作权源程序鉴别材料的研发、行政人员、独立开发者和代理机构。
- **当前差异点**：五步图形向导、带跨行字符串状态的注释清洗、显式分页、导出前风险校验、源码处理全程离线。

## 二、当前功能边界

### 核心流水线

```text
发现 Discover → 清洗 Clean → 排序截取 Select → 渲染 Render → 校验 Audit
```

| 模块 | 当前实现 |
|---|---|
| 项目导入 | 选择或拖入一个本地文件夹；支持最近项目入口 |
| 文件发现 | 后缀白名单；设置页维护应用级默认目录与文件 glob 排除规则，首次启动及恢复默认使用内置规则；与 `.gitignore` 独立叠加；探测 UTF-8、GBK 等编码 |
| 文件管理 | 真实目录树与目录三态选择、全局全选/清空/反选、入口优先/修改时间/手动排序、原始行数和文件类型构成统计 |
| 清洗引擎 | 逐字符状态机处理单行/块注释、Python docstring 与跨行字符串；删除空行；Tab 转 4 空格；78 列硬折行；敏感信息脱敏 |
| 截取分页 | 总行数不超过 3600 时全量输出；超过时按有序代码流取前 1800 行和后 1800 行；首页从首个入选文件开头开始，末页以最后一个入选文件结尾；每 60 行显式分页 |
| 文档渲染 | PDF、DOCX 使用页眉、页码、宋体 10.5pt、12pt 固定行距与显式分页；同步支持 TXT 备查文件 |
| 风险校验 | 有效内容、页眉、每页行数、末页 2/3、首末页边界、残留空行和署名冲突；根据输入条件展示对应项目 |
| 工程配置 | 将标题、著作权人、排序、文件选择、清洗开关和导出设置保存到 `.codedoc.json` |
| 桌面分发 | macOS arm64 DMG、macOS x64 DMG、Windows x64 NSIS；macOS 正式包已完成签名、公证和系统分发验证 |

### 当前明确不包含

- tree-sitter 或完整语言语法树解析
- 多目录合并导入
- 著作权人成立日期的 UI 输入
- Linux 安装包
- Windows 应用内自动下载和安装更新
- Windows 正式代码签名
- 校验项一键修复、CLI 和例外交存模式

这些能力尚未进入当前正式产品，不应在 README 或 UI 中表述为已经实现。

## 三、技术实现

### 仓库结构

```text
packages/
  core/  纯 TypeScript：discover / clean / select / render / audit
  app/   Electron 43 + React 18 + Zustand + electron-vite
```

### 关键依赖

- 文件扫描：`fast-glob`、`ignore`
- 编码识别：`chardet`、`iconv-lite`
- 注释清洗：项目内逐字符状态机，不依赖 tree-sitter
- 文档生成：`docx`
- 桌面 UI：Electron、React、Zustand、自定义 CSS
- 打包分发：`electron-builder`，目标为 macOS DMG 与 Windows NSIS

### 关键决策

1. **显式分页**：先在内存中按 60 行组成页面，再写入分页符，不依赖字体和行距凑页。
2. **状态机清洗**：识别注释、普通字符串、模板字符串和 Python 三引号字符串边界，避免正则误删字符串内容。
3. **按行精确截取**：前后段各取固定行数；整个输出的首页与末页分别锚定首个和最后一个入选文件边界，不宣称中间截点按文件原子对齐。
4. **有限并发**：异步 I/O 配合 1～4 个 worker，保留稳定排序、取消语义和主线程响应。
5. **业务与壳分离**：核心流水线不依赖 Electron，便于测试和后续复用。
6. **源码处理离线**：扫描、读取、清洗、校验和导出不发起网络请求；已打包的 macOS 应用只在版本检查和下载安装更新时访问构建时配置的发布来源。

## 四、测试与发布基线

- `npm run verify`：版本、公共 lockfile、单元/回归测试、构建和 worker 集成
- `npm run test:real-projects -w @codedoc/core -- <java-kotlin> <python> <typescript>`：三类真实项目端到端验收
- `npm run perf`：5000 文件性能基线
- 发布目标：macOS x64、macOS arm64、Windows x64
- 正式发布：先创建与源码提交一致的附注 Tag，再由本地脚本完成构建、校验、发布和回执归档

## 五、后续方向

- 多目录导入、著作权人成立日期输入和自定义清洗规则。
- 校验项辅助修复、CLI 和 Linux 支持。
- 用户手册或设计说明书模板、多申报主体和例外交存模式。
- Windows 代码签名及更新提示体验，需要专项设计和验收后再进入正式路径。
