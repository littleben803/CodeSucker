# 软著一条龙申请包（ruanzhu-one-stop）

> 把"申请软著"这件又烦又易被打回的体力活，拆成可照做的流程。核心武器是 **CodeDoc**——
> 一个离线、源码不出本机的开源工具，专门把本地代码整理成合规的 60 页源程序鉴别材料。
> 本 skill 负责把它的产出 + 你写的文档 + 申请表，串成一套便于提交前复核的材料准备稿。

---

## 一、何时使用本 skill

- 用户说"我要申请软著 / 办软著 / 登记软件著作权"
- 要准备软著申报材料（源程序鉴别材料、文档鉴别材料、申请表）
- 要把项目代码整理成符合格式的 60 页代码文档
- 要写软著用户手册 / 设计说明书
- 问软著申报流程、审查要点、为什么被补正 / 退件

---

## 二、软著是什么 & 为什么要登记

- **法律依据**：《计算机软件保护条例》《计算机软件著作权登记办法》（中国版权保护中心 ccopyright.com.cn 受理）。
- **登记不是强制**，但强烈建议：登记证书是权利归属的**初步证明**，维权、举证、交易都靠它。
- **登记的现实用途**：
  - 发生著作权争议时举证（不登记很难证明完成时间与归属）
  - APP / 小程序 / 软件产品上架（应用市场常要求）
  - 软件企业认定、高新技术企业认定、税收优惠、招投标、技术入股的知识产权证明
  - 版权贸易 / 转让时提升价值

## 三、申报材料清单（一般交存）

依据中国版权保护中心现行规则，申请文件包括：

1. **软件著作权登记申请表**：在线填报，打印带条形码的"申请确认签章页"，签章后扫描为 PDF 上传。**不得用电子签名替代手写/盖章**。
2. **软件鉴别材料**（核心，分两部分）：
   - **源程序鉴别材料**：源程序前、后各**连续 30 页**（共 60 页）；整个程序不足 60 页的提交全部；除特定情况外，**每页不少于 50 行**；页眉标注**软件全称 + 版本号**；第一页是程序开头、最后一页是程序结尾。
   - **文档鉴别材料**：用户手册 / 设计说明书等**任何一种文档**前、后各连续 30 页；每页不少于 30 行；实务建议**不少于 15 页**、图文并茂。
3. **身份证明文件**：企业交营业执照（加载统一社会信用代码）、个人交身份证等。
4. **权利归属证明**（视情况）：委托开发→委托合同；合作开发→合作合同；下达任务→项目任务书；继受取得→转让/继承/承受证明。

**例外交存（可选，替代"一般交存"的 60 页）**：当源程序含商业秘密不宜全文公开时，可在以下方式中选其一：
- a. 提交源程序前、后各连续 30 页，机密部分用**黑色宽斜线覆盖**，覆盖部分**不得超过交存源程序的 50%**；
- b. 提交源程序**连续的前 10 页 + 任何部分的连续 50 页**；
- c. 提交**目标程序**前、后各连续 30 页 + 源程序任何部分的连续 20 页。
（注：CodeDoc 默认走一般交存；例外交存需在提交时另行说明并按上述规则手动处理。）

> ⚠️ **版本号一致性（高频补正点）**：申请表、源程序页眉、文档页眉三处的软件版本号**必须一致**（带不带 "V" 以申请表填报为准）。

## 四、一条龙工作流（推荐顺序）

```
Step 1  定名与定版  → 软件名称 + 版本号（见第七节命名规范）
Step 2  生成代码材料 → 用 CodeDoc 离线抽取，产出 60 页 docx（见第五节）
Step 3  撰写文档材料 → 用户手册/设计说明书（见 references/manual-template.md）
Step 4  填申请表     → 软硬件环境、编程语言、源程序量、功能特点（见第八节）
Step 5  交叉核对     → 代码 ↔ 说明书 ↔ 申请表 三处一致性（见第九节）
Step 6  网上提交     → 中国版权保护中心上传 PDF（见第十节）
Step 7  跟踪补正     → 受理→审查→(补正30个工作日内)→发证
```

## 五、CodeDoc 集成（核心工具）

**用途**：把本地代码项目整理成符合软著格式的 60 页源程序 docx，**全程离线、源码不出本机**（相较在线工具的最大优势）。

- **品牌**：CodeDoc Generator（简称 CodeDoc）
- **协议**：Apache-2.0（允许闭源商用，再分发须附协议与 NOTICE）
- **版本**：当前工程基线为 **v0.4.4**；正式下载渠道尚未确定。
- **平台**：macOS（arm64 / x64）、Windows x64；Linux 在路线图

### 安装
- **普通用户**：正式下载渠道确定前，不要从未知第三方来源下载安装包。
- **macOS 未公证**：首次打开被拦截 →「系统设置 → 隐私与安全性 → 仍要打开」；若提示已损坏，终端执行：
  ```bash
  xattr -rd com.apple.quarantine /Applications/CodeDoc.app
  open /Applications/CodeDoc.app
  ```
- **源码运行**：
  ```bash
  cd /path/to/CodeDoc
  npm ci
  npm run dev
  ```
  - 国内 Electron 下载失败：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js`

### 五步向导
1. **导入项目**：把文件夹拖进去（递归扫描，真实目录树勾选，支持关键字筛选、按后缀只留某类文件如 `.java`）。
2. **文件与排序**：勾选纳入文件、拖拽调序、入口文件置顶。
3. **清洗与排版**：填**软件全称 + 版本号**，开关清洗规则（删注释/空行、Tab 转空格、超长行折断），有实时前后对比。
4. **分页预览**：A4 仿真 60 页缩略图，可翻看前后段分界。
5. **校验与导出**：看合规报告，生成 **docx（页眉=软件名+版本号、自动页码、宋体 10.5pt）+ txt 备查**。

### 关键能力 ↔ 软著规则映射
| 软著规则 | CodeDoc 实现 |
|----------|----------------|
| 前后各 30 页 / 共 60 页 | 超 3600 行自动取前 1800 + 后 1800；每 60 行显式分页 |
| 首页=开头、末页=结尾 | 第 1 页固定模块开头、第 60 页固定结尾 |
| 每页 ≥ 50 行 | 实打实行数，不靠排版硬凑 |
| 代码清洗 | 逐字符识别注释/字符串边界（30+ 语言），避免误删 `//` 类字符串 |
| 敏感信息 | 自动脱敏：API 密钥 / 密码 / 内网 IP / 手机号 → 占位符 |
| 提交前自检 | 行数、末页是否满 2/3、页眉、署名冲突扫描，三级结论（通过/警告/退回） |

- **辅助预判**：配套 `scripts/line_count.py` 可快速统计项目代码总行数，判断是否超过 3600 行（超过时由 CodeDoc 取前 1800 + 后 1800 行），并估算页数，提交 CodeDoc 前先用它心里有数。

> ⚠️ **导出稿是"准备稿"**：CodeDoc 自己也说最终以登记机构要求为准。提交前务必对照最新官方规定复核一遍（尤其版本号、行数、末页完整性）。

## 六、文档鉴别材料模板

CodeDoc 只生成**代码**材料，文档（用户手册/设计说明书）要自己写。直接用模板：
→ `references/manual-template.md`（含标准四章结构：概述 / 安装配置 / 功能操作 / 常见问题，及页数、截图、页眉规范）。

---

## 七、软件名称与版本号规范

- **标准格式**：`品牌/企业名 + 功能名 + 版本号`，例：`某某企业办公自动化系统V1.0`。
- **避免**：法律法规禁用词（如"国家级"最高级）、过于宽泛的通用术语（如"软件管理平台"）、与已登记软件相同或近似的名称、重复出现"软件"二字。
- **版本号**：全包三处（申请表 / 代码页眉 / 文档页眉）必须一致；带不带 "V" 以申请表为准。

---

## 八、申请表填写要点（除基础信息外）

- **硬件环境**：开发/运行软件的计算机硬件及专用设备。
- **软件环境**：开发/运行的操作系统、支持软件名称及版本号。
- **编程语言**：编写该软件的全部编程语言。
- **源程序量（行数）**：源程序总行数（与 CodeDoc 统计、说明书描述一致）。
- **主要功能和技术特点**：精简完整填写开发目的、面向领域/行业、主要功能、技术特点。
- **功能说明 / 技术特点字数**：新版申请表对该项有篇幅要求（实务约 **500–1300 字**），过短易被要求补正，须真实、具体，不得由 AI 编造。

**填写示例（某设备巡检系统）**：
| 字段 | 示例 |
|------|------|
| 软件全称 / 版本号 | XX企业设备巡检管理系统 V1.0 |
| 硬件环境 | x64 PC 8GB 内存；服务端云服务器 2 核 4G |
| 软件环境 | 客户端 Windows 10/11；服务端 CentOS 7 + MySQL 8.0 + Node.js 18 |
| 编程语言 | TypeScript、Python |
| 源程序量 | 12,800 行 |
| 主要功能和技术特点 | 面向工厂设备巡检，提供计划排程、扫码打卡、隐患上报、报表导出（500–1300 字） |

## 九、代码 ↔ 说明书 ↔ 申请表 一致性核对（必做）

审查员会交叉核验，矛盾可能被认为材料不实而被驳。重点查：
- 说明书描述的功能在源代码中有**对应实现**（避免照搬别家说明书）。
- 源代码里没有说明书**未描述**的明显功能模块。
- 说明书截图与软件实际界面一致。
- 三处软件名称 + 版本号完全一致。
- 源程序量与申请表填报行数一致。

## 十、申报流程（中国版权保护中心）

- **官网**：https://www.ccopyright.com.cn
- **著作权登记系统（公测版）**：https://register.ccopyright.com.cn
  - 注册：https://register.ccopyright.com.cn/register.html#/identity
  - 登录：https://register.ccopyright.com.cn/login.html
  - 软件登记入口：https://register.ccopyright.com.cn/registration.html#/registerSoft
  - 软件公告 / 进度查询：https://register.ccopyright.com.cn/publicInquiry.html?type=softList
- **业务类型**：选 **R11 计算机软件著作权登记申请**（2026 新版申请表已施行，旧版不予受理）。
- **步骤**：账号注册 → 实名认证（约 1–3 工作日）→ 在线填报并上传材料（PDF，单文件 ≤ 10MB，命名如 `智能排课系统_源程序_01-30.pdf`）→ 提交 → 受理 → 审查 →（可能）补正 → 发证。
- **签章页**：打印带条形码的"申请确认签章页"，**手写 / 盖章后扫描上传，不得电子签名替代**。
- **证书**：审查通过后可在用户中心下载 **电子证书（PDF）**，与纸质证书同等法律效力；也可申请纸质证书邮寄（到付）。

## 十一、费用与周期

- **官费**：自 2017-04-01 起，软件著作权**普通登记官费已取消，自助办理 0 元**（合同登记等另计）。代办机构收的是**服务费**，不是官费，注意区分。
- **加急**：官方 / 指定渠道加急仍收费，常见档：10 日加急 ¥300、5 日加急 ¥600、3 日加急 ¥1000（以最新公布为准）；加急通常需提供合理事由（如融资协议、侵权立案证明）。
- **周期**：法定"自受理日起 60 日内审查完成"；实际从提交到拿证通常 **30–60 个工作日（约 1.5–3 个月）**，遇补正顺延。
- **补正期限**：收到补正通知后 **30 日内**补正，逾期视为撤回。

---

## 十二、审查要点 & 常见补正避坑

| 补正原因 | 应对 |
|----------|------|
| 源代码不足 60 页 / 每页不足 50 行 | CodeDoc 自动保证；提交前再数一遍末页 |
| 说明书篇幅不足 / 过简（建议 ≥15 页） | 用模板扩充功能描述 + 界面截图 |
| 功能说明字数过少（建议 500–1300 字） | 写实写具体，覆盖开发目的 / 领域 / 功能 / 技术特点 |
| 说明书与源代码不一致 | 第九节交叉核对 |
| 软件名称不规范 / 重复 | 第七节重命名 |
| 版本号三处不一致 | 统一命名 |
| 敏感信息未脱敏（密钥 / 内部 IP） | CodeDoc 自动脱敏；或例外交存黑线覆盖（≤50%） |

## 十三、2026 合规提醒（AI 辅助声明）

- 2026 起新版申请表新增关于**"是否使用 AI 开发代码 / 撰写文档 / 生成申请材料"的声明与签署**要求（以官方最新申请表为准）。
- 本 skill 的模板与 CodeDoc 产出**仅作起草辅助**：提交前你必须把说明书**改写 / 审校为真实反映自身开发情况**的内容，并独立承担声明真实性责任。
- 切勿照搬别家说明书或让 AI 编造功能——审查员会核验"说明书功能 ↔ 源代码实现"的一致性，矛盾可能被认定材料不实。

---

## 十四、适用边界与 CodeDoc 局限

- CodeDoc **只解决"源程序鉴别材料"** 的格式化生成；**申请表、文档鉴别材料（用户手册 / 设计说明书）、身份证明、权属证明仍需自行准备**。
- CodeDoc **不替代**官方审查，导出稿是"准备稿"，提交前须自行复核版本号、页数、末页完整性。
- 源程序**不足 60 页**时，按规则**提交全部代码**（CodeDoc 亦按实际处理），无需硬凑页数。
- 外国主体、涉外公证认证、复杂继受（转让 / 继承 / 承受）、职务作品等情形规则更复杂，建议咨询专业人士或代理机构。

## 十五、重要免责

软著规则会调整，**所有格式要求以中国版权保护中心（ccopyright.com.cn）最新公布为准**。
本 skill 提供工作流、模板与工具指引，不替代法律或代理机构专业意见；涉及权属争议、涉外、复杂继受等情形建议咨询专业人士。
